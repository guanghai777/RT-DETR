# 新服务器部署指南（快速版）

目标：在一台全新的服务器（AutoDL / 实验室 GPU 机器）上，从本仓库 + 两份外部资源
（**魔改 ultralytics 框架**、**数据集**）快速恢复训练环境。

> 本仓库的 git 只管理**代码**：改进模型 yaml、训练/验证脚本、配置与文档。
> 框架源码（约 22M）和数据集（约 185M）不入库，需要按下面步骤单独拷贝。

---

## 0. 约定

以下命令假设：

- 项目部署在 `/root/rtdetr-improve`（仓库根目录）
- 旧实例上的完整项目在 `/root/RTDETR-20260410/`
- 旧实例 SSH：`ssh -p <旧端口> root@<旧地址>`（AutoDL 形如 `connect.cqa1.seetacloud.com`）
- 新服务器已能用 SSH 登录

如果只在本地机器操作，把 `/root/rtdetr-improve` 换成你的本地路径即可。

---

## 1. 获取本仓库

```bash
# 方式一：从本地已整理好的目录同步（推荐，附带本地框架副本时可只同步 git 内容）
rsync -av --exclude .git /home/pan/project/rtdetr-improve/ root@<新服务器>:/root/rtdetr-improve/

# 方式二：如果仓库推到了 git 远端
git clone <仓库地址> /root/rtdetr-improve
```

进入项目：

```bash
cd /root/rtdetr-improve
```

## 2. 拷贝魔改 ultralytics 框架（必须）

框架是原项目基于 ultralytics 8.0.201 的魔改版，包含 `nn/extra_modules` 等自定义模块，
**不能**用 `pip install ultralytics` 替代。

### 2.1 从旧实例流式传输（出网限速时用 tar，别用 rsync 逐文件）

```bash
# 在【新服务器】上执行
ssh -p <旧端口> root@<旧地址> \
  "tar -C /root/RTDETR-20260410 -cf - ultralytics" \
  | tar -C /root/rtdetr-improve -xf -

# 框架里也带着一份 cfg/models，覆盖后从 git 恢复仓库管理的版本
cd /root/rtdetr-improve
git checkout -- ultralytics/cfg/models
```

### 2.2 或从本地机器直接上传

```bash
# 在【本地机器】执行
rsync -avz --exclude 'cfg/models' \
  /home/pan/project/RTDETR-20260410/ultralytics/ \
  root@<新服务器>:/root/rtdetr-improve/ultralytics/
```

> 旧实例出网被限速到约 100 KB/s，框架 22M 大约 4~5 分钟，建议放 `tmux` 里跑。

验证：

```bash
cd /root/rtdetr-improve
python -c "from ultralytics import RTDETR; print('framework OK')"
```

如果报 `No module named 'einops' / 'timm' / 'pytorch_wavelets'`，先做第 3 步。

## 3. 创建 Python 环境

推荐：**Python 3.10 + PyTorch 2.0 ~ 2.5 + CUDA 11.8 / 12.1**。
AutoDL 新建实例时选带 PyTorch 2.x 的镜像，torch 已预装，可跳过 torch 安装。

```bash
# 非 AutoDL 机器
conda create -n rtdetr python=3.10 -y
conda activate rtdetr
# 显卡驱动对应 CUDA 11.8 时：
pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu118

# 安装其余依赖（自动跳过已安装的 torch；默认用清华镜像）
bash scripts/setup_env.sh

# 需要跑 tools/ 里的热力图、COCO 指标等脚本时
bash scripts/setup_env.sh --with-tools
```

装完执行自检：

```bash
python scripts/check_env.py
```

它会检查：依赖包、CUDA、ultralytics 能否导入、默认模型 `improve-Copy1.yaml` 能否构建、
数据集路径是否存在。**全部 OK 再继续。**

### 关于 torch 2.6+

torch 2.6 起 `torch.load` 默认 `weights_only=True`，加载旧版 `.pt` 会报
`Weights only load failed`。二选一：

- 换回 `torch<=2.5`；或
- 运行前设置：`export TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1`

## 4. 拷贝数据集（必须）

目录结构必须为：

```

├── images/{train,val,test}/
```

传输（旧实例 → 新服务器，约 185M，限速下约 30 分钟，务必放后台）：

```bash

  | tar -C /root/rtdetr-improve/datasets -xf -
mv /root/rtdetr-improve/datasets/dataset /root/rtdetr-improve/datasets/insulator
```

或从本地传输：

```bash
rsync -avz /home/pan/project/RTDETR-20260410/dataset/ \
  root@<新服务器>:/root/rtdetr-improve/datasets/insulator/
```

> 旧实例上的 `dataset/data.yaml` 写死了 `/root/RTDETR-20260410/` 绝对路径，**不要使用**。
> 本仓库统一使用 `configs/datasets/insulator.yaml`（相对路径，换服务器无需修改）。

## 6. 启动训练 / 验证 / 推理

```bash
# 训练（默认 improve-Copy1.yaml + 7 类绝缘子数据集）
python train.py

# 指定其它改进 yaml / 输出名
python train.py --model ultralytics/cfg/models/rt-detr/improve/improve.yaml --name exp_lsblock
python train.py --epochs 300 --batch 8 --device 0

# 后台训练
nohup python train.py > train.log 2>&1 &

# 验证（默认读取 runs/train/exp/weights/best.pt，输出论文指标表）
python val.py                    # 默认 split='test'，对应 images/val
python val.py --weights runs/train/exp2/weights/best.pt

# 推理
python detect.py --source datasets/insulator/images/test
```

输出统一在 `runs/` 下（不入库）。

## 7. 可选：CUDA 扩展模块

默认模型 `improve-Copy1.yaml`（LGLB + LRSA + SNI + RepC3 + GSConvE）**不需要**编译任何
CUDA 扩展。以下扩展只在使用对应 yaml 时才需要，按需安装：

| 模块 | 位置 / 安装 |
| --- | --- |
| DCNv3 | `cd ultralytics/nn/extra_modules/ops_dcnv3 && python setup.py build install`（`dist/` 下的 whl 仅适用于 Python 3.8） |
| DCNv4 | `cd ultralytics/nn/extra_modules/DCNv4_op && python setup.py build install` |
| mamba / selective_scan | `ultralytics/nn/extra_modules/mamba/`、`selective_scan/`，要求和 torch/CUDA 版本严格匹配 |
| KAT | `cd ultralytics/nn/extra_modules/rational_kat_cu && python setup.py build install` |
| mmcv / mmengine | `pip install mmcv mmengine`，需与本机 torch/CUDA 匹配 |

逐项验证：

```bash
python tools/test_env.py
```

> 框架对缺省扩展做了 try-except 兼容（如 DCNv3 会退回纯 PyTorch 实现），
> 不影响导入，但对应模块的运行速度会下降。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| `No module named 'ultralytics'` | 框架没拷到项目根目录，见第 2 步 |
| `No module named 'einops' / 'timm' / 'pytorch_wavelets'` | `bash scripts/setup_env.sh` |
| `Weights only load failed` | 见第 3 步 torch 2.6+ 说明 |
| 数据集找不到 / 路径错 | 执行 `python scripts/check_env.py` 看具体哪个 split 缺；核对 `datasets/insulator/` 结构 |
| CUDA out of memory | 调小 `--batch`；或 `PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:128` |
| DataLoader 卡死 | `--workers 0` |
| `libcudart.so: cannot open shared object file` | torch 与 CUDA 驱动不匹配，重装对应 CUDA 版本的 torch |
| 训练很慢、GPU 利用率低 | 确认 `torch.cuda.is_available()` 为 True，`--device 0` |
